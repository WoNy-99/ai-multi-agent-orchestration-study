# 구현 및 검증 계획

**모든 실행 항목은 미착수 또는 미수행입니다. 일정·성능 목표를 달성했다고 표시하지 않습니다.**

## 최소 범위부터 시작하는 계획

1. 역할·상태·허용 전환·실패 처리·근거 형식을 작게 고정합니다.
2. 실제 AI를 연결하기 전에 모의 Worker / Reviewer로 상태 전환과 반려·재시도를 시험합니다.
3. 하나의 공급자 연결부터 시간 제한·오류 분류·중단을 확인합니다.
4. 읽기 전용 검수와 별도 QA의 실행 경계를 시험합니다.
5. 근거·문서·복구 상태의 연결을 확인한 뒤 마스터 연결을 검토합니다.
6. 장시간 운영·병렬화·자동 재개·관측 도구는 이후 단계로 남깁니다.

원 명세의 최종 구상은 범위가 넓습니다. 대화에서 기존 도구만으로 운영하는 단순한 대안도 논의했으나, 실제 적용 이력은 없습니다.

## 완료를 주장하기 전에 필요한 것

구현 코드, 고정된 시험 조건, 실제 실행 기록, 실패 및 복구 결과, 남은 위험과 승인 범위가 필요합니다. 문서 검토만으로 `PASSED` 상태를 채우지 않습니다. 현재는 어느 항목도 운영 완료로 승격하지 않습니다.
